# TXT GAME BOX

텍스트 게임 여러 개를 담은 상자입니다. 첫 화면에서 게임을 고르면 그 게임만 내려받아 실행합니다. 휴대폰 브라우저에서 바로 돌아가는 PWA이고, 모든 데이터는 기기 안에만 저장됩니다.

이 프로젝트는 텍스트 게임 장르에 대한 개인 오마주입니다. 사건, 결말, 이름, 픽셀 아트는 전부 이 저장소에서 새로 만든 창작물이며, 어떤 상용 게임의 텍스트나 자산도 포함하지 않습니다.

## 실행

Node 24와 pnpm이 필요합니다. 저장소에 `.nvmrc`가 있습니다.

```sh
nvm use
pnpm install
pnpm dev --host
```

터미널에 나오는 `Network` 주소를 같은 Wi-Fi의 휴대폰에서 열면 됩니다.

오프라인 동작과 홈 화면 설치는 빌드 결과물에서만 켜집니다. `localhost` 또는 https에서만 서비스 워커가 등록됩니다.

```sh
pnpm build
pnpm preview --host
```

## 수록 게임

### 모험가 이야기

중세 판타지 세계를 떠도는 모험가가 되어 사건을 고르고, 주사위를 굴리고, 결말을 모으는 텍스트 로그라이크입니다. 하루에 사건 하나를 만나고, 능력치와 소지품이 열어 주는 선택지를 골라 20면체 주사위 판정을 넘깁니다. 경험치 100에 닿으면 여정이 끝나고, 모은 결말과 몬스터와 아이템은 도감과 랭킹에 남습니다.

1. **캐릭터 생성.** 이름, 출신 3종 중 하나, 특성 10종 중 하나를 고릅니다. 여정(서브 스토리) 3종을 켤 수 있고, 어려움 모드를 선택할 수 있습니다. 여섯 능력치(힘, 민첩, 지능, 카리스마, 건강, 지혜)는 각각 4에서 시작하며 18포인트를 나눠 담습니다. 한 능력치의 시작 상한은 10입니다.
2. **사건.** 하루에 사건 하나가 나옵니다. 선택지는 능력치, 아이템, 골드, 특성, 이전 선택에 따라 열리거나 닫힙니다. 닫힌 선택지에는 이유가 함께 표시됩니다.
3. **판정.** 판정은 20면체 주사위에 능력치를 더해 목표치와 비교합니다. 20은 항상 성공, 1은 항상 실패입니다.
4. **전투.** 매 라운드 주사위를 굴립니다. 20이면 즉시 승리, 1이면 방어를 무시한 두 배 피해를 받습니다. 도주는 민첩 판정입니다.
5. **성장.** 경험치가 10 오를 때마다 능력치 포인트를 받습니다. 경험치가 100에 닿으면 모험이 끝납니다. 체력이나 정신력이 0이 되어도 끝납니다.
6. **결말과 기록.** 출신마다 좋은 결말과 나쁜 결말이 하나씩, 여정마다 결말이 하나씩 있습니다. 결말, 마주친 몬스터, 얻은 아이템은 도감에 쌓이고 점수는 랭킹에 남습니다.

저장은 매 사건 뒤 자동으로 됩니다. **불러오기**를 3회 이상 쓰면 그 모험은 랭킹에서 제외됩니다. 타이틀의 **이어하기**는 횟수를 세지 않습니다.

|---|---|
| 사건 | 84 (공통 51, 출신 18, 여정 15) |
| 결말 | 12 |
| 아이템 | 40 |
| 몬스터 | 20 |
| 특성 | 10 |

### 정적의 항로

빛보다 느린 이주선의 함장이 되어 30일 항해를 지휘하는 격리 게임입니다. 배가 계속 가속하는 탓에 지구의 답신은 갈수록 늦게 도착합니다. 지연은 1일에서 시작해 최대 7일까지 벌어지고, 함장이 읽는 증상 보고서는 늘 며칠 지난 이야기입니다. 여덟 명 중 누가 감염되었는지 낡은 정보로 짚어 격리해야 하지만, 갇힌 승무원은 스트레스가 쌓이고 스트레스가 쌓인 승무원은 함장에게 맞섭니다.

1. **하루.** 통신 → 관찰 → 행동 → 밤 순으로 진행합니다. 통신 단계에서 그날 도착한 지구 메시지가 증상 정보를 확정하거나 뒤집습니다.
2. **행동.** 하루에 행동 점수 2점을 씁니다. 격리, 격리 해제, 검사, 대화, 치료 다섯 가지입니다. 의무관이 앓거나 죽으면 검사 결과가 확률로 뒤집힙니다.
3. **밤.** 잠복이 진행되고, 발병한 승무원은 네 번째 밤에 죽습니다. 격리된 승무원은 스트레스가 더 빨리 오르고, 한계에 닿으면 함장에게 대치를 걸어옵니다.
4. **결말.** 30일을 넘기면 **도착**입니다. 그 전에 **정적**(전염 붕괴), **반란**, **빈 함교**(함장 사망)로 끝날 수 있습니다.

|---|---|
| 승무원 | 8 |
| 사건 | 16 |
| 지구 통신 | 12 |
| 증상 | 6 |
| 대치 | 4 |
| 결말 | 4 |

### 복구 기록

괴수와 히어로의 싸움이 끝난 자리를 치우는 토목 회사의 젊은 사장이 되어, 1인칭으로 하루를 버팁니다. 회사는 싸우지 않습니다 — 협회가 보낸 공문의 마감은 늘 정오이고, 현장에 데려갈 사람을 고르는 것도 무엇을 보고할지 정하는 것도 사장 몫입니다. 회차는 네 곳의 일감을 차례로 지나고, 두 사람의 사정이 같은 달력에 얹힙니다: 자격이 만료된 전직 히어로 강두식과, 사람들 사이에서 무언가 다른 루.

1. **사무실.** 하루는 사무실에서 시작합니다. 협회 발표가 라디오로 흐르고 동료들이 말을 겁니다. 프린터에서 공문을 뽑으면 그날의 일감이 정해집니다.
2. **공문.** 공문이 화면 가득 펼쳐집니다 — 발신명의, 문서번호, 수신, 번호가 붙은 항목, 직인생략. 마감과 조건이 여기 적혀 있습니다.
3. **인원 선택.** 그 일감에 데려갈 사람을 1~2명 고릅니다. 누구를 데려가느냐가 현장에서 보이는 것과, 그 사람들의 상태(피로·부상·의심·신뢰)를 함께 바꿉니다. 다친 사람은 다음 일감을 결장합니다.
4. **뒷정리.** 현장에 들어가기 전에 지침서대로 작업 순서를 정합니다 — 안전 표지와 통제선, 전원과 가스관 차단, 잔해 안쪽 확인, 위치와 수치 기록. 순서를 제대로 세운 현장에서는 그날 다치는 사람이 나오지 않습니다. 버튼은 지침 순서대로 놓여 있지 않으니 지침서를 읽어야 합니다.
5. **현장.** 현장 문서를 확인하고 사건을 처리합니다. 여기서 확보한 것(좌표·단서·문서·물건)이 조건을 만족하면 관문·수신자·군 접점 같은 절차가 일감 사이에 끼어듭니다.
6. **다음 일감.** 처리가 끝나면 다음 날 아침 사무실로 돌아갑니다. 일감은 관악구 현장 → 천체관측소 → 협회 본부 → 최종 정리 폐허 순으로 한 번씩 나옵니다.

**종결.** 인물마다 진엔딩이 하나씩 있고 한 회차에 하나만 성립합니다. 그 밖에 일반·일상·사망 엔딩이 있습니다. 잠기는 갈래는 화면에 이유를 밝히고, 다시 열 기회가 남아 있으면 재등장으로 이어집니다. 배태산과 최 반장의 결말은 루트가 아직 기획되지 않아 종결 집합에서 제외했습니다. 미달성 종결의 이름은 기록 화면에서 `???`로 가려지고, 그 결말에 도달한 화면에서만 공개됩니다.

| 항목 | 수 |
|---|---|
| 일감 | 4 |
| 일감 처리 순서 | 5 (사무실·공문·인원 선택·뒷정리·현장) |
| 뒷정리 작업 | 4 |
| 액션 | 48 |
| 종결 | 7 |
| 인물 | 4 |

저장은 행동마다 자동으로 됩니다. 타이틀의 **이어하기**로 이어서 할 수 있습니다.

## 개발

```sh
pnpm verify   # 타입 검사, 린트, 테스트
pnpm build    # 정적 빌드와 서비스 워커 생성
```

| 폴더 | 역할 |
|---|---|
| `src/shared` | 어느 게임도 소유하지 않는 코드. UI 기본 요소, 픽셀 스프라이트 렌더러, 조사 처리, 난수, 주사위, uuid, 저장 슬롯. |
| `src/host` | 첫 화면, 게임 목록, 테마 주입, PWA 껍데기. 각 게임의 `meta.ts`만 정적으로 읽고 본체는 필요할 때 내려받습니다. |
| `src/worlds/<id>` | 게임 하나. `meta.ts`, `theme.ts`, `world.ts`와 `content/`, `ui/`, `store/`, `editor/`를 가집니다. 규칙 코드는 `모험가 이야기`가 `engine/`, `정적의 항로`가 `rules/`에 둡니다. |
| `src/editor` | 콘텐츠 편집기 화면. 개발 모드에서만 실행됩니다. |
| `tools/content-editor` | 편집기의 저장 서버. Vite 개발 서버 플러그인입니다. |

현재 등록된 게임은 `adventurer`(모험가 이야기), `voyage`(정적의 항로), `reclaim`(복구 기록)이며, 목록은 `src/host/registry.ts`에 있습니다.

`reclaim`의 두 배치(`ru_first` / `dusik_first`)는 이야기 체인의 순서를 정하는 규칙 파라미터입니다. 두 배치는 같은 흐름과 같은 콘텐츠를 공유하고 guard와 간선만 바꾸며, 캐논은 아직 보류 상태입니다 — 제품 화면에 노출하지 않고 `RunState.placement`로 저장됩니다.

콘텐츠 편집기가 있습니다. `pnpm dev`를 실행하고 `http://localhost:5173/__content?world=adventurer`를 엽니다. `?world=`에 게임 id를 넣어 편집할 게임을 고르고, 생략하면 첫 번째 게임이 열립니다. 사건과 결말의 글을 화면에서 고치고 **저장**을 누르면 `src/worlds/<id>/content`의 소스 파일이 그대로 바뀝니다. 이 페이지는 개발 모드에서만 열리며 빌드 결과물에는 들어가지 않습니다. 편집기 안의 시험 플레이는 메모리에만 저장되므로 실제 저장 파일, 도감, 랭킹을 건드리지 않습니다. `reclaim`은 이번 범위에서 편집기를 붙이지 않았으므로, 글은 `src/worlds/reclaim/content/`의 소스에서 고칩니다.

기술 스택은 Vite 8, React 19, TypeScript 7, Tailwind 4, Zustand 5, zod 4, Vitest 5, Biome 2입니다. 글꼴은 Galmuri11이며 SIL Open Font License 1.1로 배포됩니다. 색은 게임마다 16색 팔레트를 따로 선언합니다.
