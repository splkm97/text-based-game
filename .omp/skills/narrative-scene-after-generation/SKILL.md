## 목적

작성·수정 직후의 장면 하나를 격리된 작업 디렉터리에서 검토해, 장면이 1인칭 정보 경계·인과·선택지·원장과 어긋나는 지점을 근거 위치와 함께 남긴다. 장면을 고치지 않고, 승인 여부와 즉시 수정·후속 검토 항목을 분리해 호출자에게 돌려준다.

## 사용 시점

- 장면 하나를 막 작성했거나 수정해, 다음 장면으로 넘어가기 전에 검토가 필요할 때.
- 장면의 선택지·정보 공개·후속 인과가 원장과 어긋나는지 확인할 때.
- 장면 승인 여부와 즉시 수정 목록이 필요할 때.

## 사용하지 말아야 할 때

- 장면을 설계하거나 선택지를 만들 때는 `scene-architect`를 사용한다. 이 스킬은 이미 작성된 장면만 검토한다.
- 인물이 왜 그렇게 행동하는지의 타당성을 판단할 때는 `character-simulator`를 사용한다.
- 원장·원고 사이의 사실 모순을 전수 대조할 때는 `continuity-auditor`를 사용한다.
- 독자가 `뻔하다`·`설명이 많다`라고 느낄 후보를 뽑을 때는 `red-team-reader`를 사용한다.
- 본문을 다시 쓸 때는 `narrative-rewriter`를, 원장을 수정할 때는 `remains-ledger-maintenance`를 사용한다. 이 스킬은 진단만 하고 원본을 고치지 않는다.

## 공통 계약

`RUN_DIR`(=`.outline/<RUN_ID>/`) 안의 산출물만 사용해 검토한다. 외부 프로젝트 경로는 읽지 않는다. 죽음, 배신, 전투 결과, 시스템, 통화, 플레이 시간, 확률, 비밀 신원 또는 제공된 범위를 벗어난 사실을 만들지 않는다. 확인된 근거, 예상되는 플레이어 경험, `판단 자료 부족`을 구분한다. 모든 중요한 발견에는 입력 스냅샷의 줄 범위·장면 제목·선택지 또는 명시적 원장 항목을 붙인다. 해결되지 않은 Critical/Major 모순이나 작성된 장면의 결함에는 `FAIL`, 후속 장면 또는 상태 근거가 없으면 `UNVERIFIABLE`, 그 외에는 `PASS`를 사용한다. 포맷터, 린터, 테스트, 빌드, 커밋 또는 게시 명령을 실행하지 않는다.

## 작업 디렉터리

- 호출자가 제공한 인라인 입력으로 고유한 `RUN_ID`를 정하고, 존재하지 않는 `.outline/<RUN_ID>/`를 먼저 만든다. 생성한 `.outline/<RUN_ID>/`를 `RUN_DIR`로 사용한다. 이미 존재하면 `input-blocked`로 처리한다.
- `RUN_ID`와 `SCENE_ID`는 `[A-Za-z0-9_-]+` 형식만 허용한다.
- 인라인 입력을 `RUN_DIR/inputs/manifest.json`과 스냅샷으로 기록한다. manifest에는 `runId`, 입력·중간 산출물·출력별 `role`, `relativePath`, `sha256`, 선택적 `sourceVersion`을 기록한다.
- 모든 `relativePath`를 정규화하고 절대경로·`..`·심볼릭 링크·`RUN_DIR` 이탈을 거부한다. 실제 스냅샷 해시가 manifest의 `sha256`과 일치해야 한다.

## 출력 안전

`RUN_DIR/outputs/scenes/<SCENE_ID>.md`만 작성한다. 출력 경로를 정규화한 뒤 `RUN_DIR` 하위인지 확인하고 심볼릭 링크를 거부한다. 원본과 기존 보고서는 수정하지 않는다. 필수 입력이 없으면 `input-blocked`로 처리한다.

## 입력

- 장면 ID와 제목 번호.
- 변경 장면, 바로 앞 장면, 작성된 후속 장면의 인라인 내용.
- 관련 설정 원장의 인라인 내용.
- 제공된 인물·세계 제약.

장면 ID 또는 필요한 인라인 입력이 없으면 `input-blocked`로 처리하고 파일을 작성하지 않는다.

## 지문

- `Reviewed commit`: 호출자가 제공한 현재 소스 커밋. 없으면 `input-blocked`다.
- `Reviewed artifact SHA-256`: 제공된 변경 장면 스냅샷의 SHA-256. 계산하거나 확인할 수 없으면 `input-blocked`다.

## 절차

1. 실행 디렉터리를 만들고 인라인 입력을 manifest와 스냅샷 파일로 기록한다. 완료 조건: `RUN_DIR`이 새로 만들어졌고 모든 manifest 항목의 `relativePath`가 `RUN_DIR` 하위이며 스냅샷 해시가 `sha256`과 일치한다.
2. manifest와 스냅샷만 읽어 장면, 선행 장면, 후속 장면, 관련 원장을 확인한다. 완료 조건: 보고서에 인용한 모든 근거가 `RUN_DIR/inputs/` 스냅샷의 `파일:줄` 또는 장면 제목으로 표기된다.
3. 1인칭 정보 경계를 확인한다. 비밀이거나 나중에 공개되거나 주인공이 아직 알 수 없는 사실을 노출하지 않는다. 완료 조건: 노출 금지 사실마다 노출·미노출·`판단 자료 부족` 판정과 근거 위치가 하나씩 있다.
4. 장면의 새 정보, 갈등, 결정, 결과를 확인한다. 완료 조건: 네 항목이 각각 채워지고, 없는 항목은 `없음`으로 적는다.
5. 각 `(S)` 선택지의 이유, 보이는 위험, 구별되는 즉시 결과, 작성되었거나 명시적으로 보류된 다음 상태를 확인한다. 완료 조건: 모든 `(S)` 선택지가 네 필드를 갖고, 각 필드에 근거 위치 또는 `판단 자료 부족` 표시가 있다.
6. 선행 사건의 인과관계와 후속 장면의 존재를 추적한다. 미래 장면이 없으면 발명하지 않고 `UNVERIFIABLE` 또는 보류로 표시한다. 완료 조건: 후속 근거가 없는 항목마다 `UNVERIFIABLE` 또는 보류 표시가 있고, 발명한 후속 내용이 하나도 없다.
7. 원장과 인물 지식, 동기, 용어, 세계 규칙, 공개·비공개 정보를 대조한다. 완료 조건: 대조한 원장 항목마다 원장 위치와 일치·불일치 판정이 있다.
8. NPC의 욕망과 행동, 플레이어 대상 언어, 선택지와 구현 표식의 분리를 확인한다. 완료 조건: 세 항목 각각에 판정과 근거 위치가 있다.
9. 이후 클라이맥스, 최종 공개, 엔딩 해결을 조기에 사용하지 않았는지 확인한다. 완료 조건: 조기 사용 항목이 있으면 severity와 근거 위치가 있고, 없으면 `없음`으로 적는다.
10. 근거가 있는 발견만 기록하고 즉시 수정과 후속 엔딩 검토 항목을 구분한다. 완료 조건: 모든 발견이 `Immediate fixes` 또는 `Deferred checks` 중 하나에 배정되고, 근거 없는 발견이 없다.
11. `RUN_DIR/outputs/scenes/<SCENE_ID>.md`에 결과를 작성한다. 완료 조건: 출력 파일 하나에 필수 10개 섹션과 닫힌 어휘의 판정이 들어 있다.

## 출력 계약

- 경로: `RUN_DIR/outputs/scenes/<SCENE_ID>.md` 한 파일. 정규화 후 `RUN_DIR` 하위여야 하고 심볼릭 링크를 거부한다.
- 필수 섹션 10개: `Scene`, `Reviewed commit`, `Reviewed artifact SHA-256`, `Status`, `Scope`, `Evidence`, `Findings`, `Immediate fixes`, `Deferred checks`, `Limitations`.
- `Status`는 `PASS|FAIL|UNVERIFIABLE`만 쓴다. 각 발견은 severity(`Critical|Major|Minor`), status(`open|resolved`), 근거 위치(`파일:줄`), 결과, 장면 승인 차단 여부를 포함한다.
- 호출자 반환: `RUN_DIR` 경로와 `Status`. `input-blocked`면 파일 없이 부족한 입력 목록을 돌려준다.

## 실패 처리

- **input-blocked:** `SCENE_ID`가 없거나, 필수 인라인 입력이 없거나, `RUN_ID`가 이미 존재하거나, `relativePath`·스냅샷 해시 검증에 실패하거나, `Reviewed commit`·`Reviewed artifact SHA-256`이 없는 경우. 파일을 작성하지 않고 부족한 입력을 나열한다.
- **missing-source-evidence:** 후속 장면·상태 근거가 없어 판정할 수 없는 경우. 해당 발견만 `UNVERIFIABLE`로 표시하고 나머지 검토는 계속해 파일을 작성하며, 확인하지 못한 범위를 `Limitations`에 남긴다.
- **knowledge-leak:** 1인칭 정보 경계 위반을 발견한 경우. 발견을 삭제하지 않고 severity와 근거를 붙여 기록하고 `Status`를 `FAIL`로 쓴다.
- **path-escape:** 정규화 후 출력 경로가 `RUN_DIR`을 벗어나는 경우. 파일을 작성하지 않고 거부한다.
- **unknown-scene:** 제공된 `SCENE_ID`가 입력 내용과 맞지 않는 경우. 유사 장면을 추측해 대체하지 않고 파일을 작성하지 않는다.
- **evidence-missing:** 발견에 붙일 근거 위치가 없는 경우. 그 발견을 기록하지 않고, 근거를 찾지 못한 항목으로 `Limitations`에 옮긴다.

## 금지

- 장면 본문, 원장, 기존 보고서 수정.
- 발명한 후속 장면·상태·수치로 빈칸을 채우는 것.
- 근거 없는 발견을 severity와 함께 기록하는 것.
- `PASS` 판정을 위해 정보 경계 위반이나 선택지 결함을 누락하는 것.
- 포맷터, 린터, 테스트, 빌드, 커밋, 게시 명령 실행.
