참조 문서 · 분기 서사 스킬 surface

스킬 지도 — 왜 있고, 무엇이 다른가

스킬 목록이 아니라 경계를 외운다. 각 항목은 "왜 이 스킬이 존재하는가"와 "가장 가까운 이웃과 무엇이 다른가"로만 적었다. 어디에 앉는지는 워크플로우 한 장을 본다.

3초 판정 — 증상에서 스킬로

증상스킬그 스킬이 보는 것 / 보지 않는 것
"이 인물이 왜 이래?"character-simulator인물 상태에서 나온 행동 후보 3개 / 플롯에 협조하는 해석
"설정이 안 맞는다"continuity-auditor시간·장소·소지품·관계·지식 등 11개 영역의 사실 모순 / 재미와 문체
"이 장면 없어도 되지 않아?"structural-critic삭제·변화 테스트와 수정 방향 A/B / 수정문 자체
"뻔하고 설명이 많다"red-team-reader독자 반응 후보와 Confidence / 재작성

여덟 증상이 서로 다른 스킬인 이유는 하나다. 같은 원고를 보면서도 서로 다른 것을 판정하고, 서로 다른 것을 금지한다. 그래서 진단을 하나로 합치면 각 스킬이 지키는 금지선이 사라진다.

라우터

스킬왜 필요한가무엇이 다른가
novel-workflow 요청이 두 단계 이상을 요구할 때 순서를 즉흥적으로 정하면 게이트가 조용히 빠진다. 특히 한 요청이 두 신호를 동시에 만족할 때(그때는 뒤 단계를 모드로 삼고 앞 단계는 게이트만 확인한다). 다른 어떤 스킬도 하지 않는 일을 한다 — 후보·진단·판정·문장을 전부 만들지 않고 순서·게이트·위임만 정한다. 단일 스킬로 끝나는 요청에는 이 스킬을 쓰지 않고 그 스킬을 직접 부른다. G28~G30 체인도 이 라우터의 모드가 아니다(순서가 이미 고정).

상류 surface — 만들고 진단하되 판정하지 않는다

스킬왜 필요한가무엇이 다른가
divergent-ideator 사람은 20개 중에서 고르는 일은 잘하지만 20개를 동시에 떠올리지는 못한다. 탐색 공간을 넓히는 일과 고르는 일을 분리한다. scene-architect가 장면 사양을 확정하는 것과 달리 후보만 낸다. dialogue-variator가 대사 하나를 변주하는 것과 달리 사건·선택지 규모를 다룬다. 후보에 [FACT]를 아예 쓸 수 없고, 최종 선택은 사람이 한다.
character-simulator 인물이 플롯에 협조하는 사고를 막는다. "이야기가 이렇게 흘러야 하므로"는 이 스킬에서 금지된 근거다. continuity-auditor가 텍스트와 정본의 모순을 보는 것과 달리, 이 스킬은 아직 쓰지 않은 상황에서 그 인물이 택할 행동 후보 3개를 만든다. 그중 최소 하나는 그 인물에게 불리해야 한다 — 플레이어가 원하는 결과를 기준으로 고르지 않는다.
scene-architect 산문을 먼저 쓰면 문장은 좋은데 아무것도 변하지 않는 장면이 나온다. 진입·종료 상태와 인과를 먼저 고정한다. reverse-outliner가 이미 쓴 원고에서 구조를 뽑는 것(과거)과 달리, 이 스킬은 앞으로 쓸 장면의 사양을 쓴다(미래). structural-critic은 문제만 진단하고 수정문을 쓰지 않는다. turn이 서지 않거나 상태가 변하지 않으면 완성으로 표시하지 않는다.
dialogue-variator 네 인물의 말투가 같아지고, 한 의도가 한 높이로만 말된다. 같은 의도를 여러 subtext로 다시 말하게 한다. divergent-ideator의 branch 모드가 선택지(사건)를 늘리는 것과 달리, 이 스킬은 이미 정해진 표면 의도 하나만 다시 말한다 — 줄거리·사건·설정을 바꾸는 대안은 금지다. 원장의 voice 규칙이 없으면 결과가 [HYPOTHESIS]로 낮아진다(unverifiable-voice).
structural-critic 삭제 테스트에 걸리는 장면이 쌓이면 후반이 무너진다. 장면 필요성·반복·우연 의존·클라이맥스 준비를 먼저 본다. reverse-outliner가 15필드 표를 뽑는 것과 달리 표 없이 문제만 진단하고, 수정문 대신 방향 A/B만 낸다. 취향 차이를 결함으로 단정하지 않고, 등급·점수도 매기지 않는다.
continuity-auditor 설정 모순은 사람 눈에 띄지 않고, 원고가 나간 뒤 회수하는 비용이 크다. 시간·장소·소지품·신체·관계·세계 규칙·시점·복선 등 11개 영역을 전수로 훑는다. 재미·페이싱·문체를 판정하지 않는다(명시적 금지). character-simulator가 동기의 타당성을 보는 것과 달리, 이 스킬은 사실 모순과 지식 경계 위반(인물이 알 수 없는 사실을 근거로 쓴 경우)만 본다. 근거가 한쪽뿐이면 Held checks로 보내고 단정하지 않는다.
red-team-reader 자기 원고는 자기에게 재미있다. 가혹한 독자를 대신 세운다 — 원고를 처음 읽는 사람이 어디서 실망하고 이탈하는지. structural-critic이 원리(인과·필요성)로 진단하는 것과 달리, 이 스킬은 반응 후보만 낸다. 칭찬·총평·재작성을 금지하고 출력에 Do NOT rewrite를 박는다. Confidence로 취향과 결함을 갈라 결함 단정을 막는다.
reverse-outliner 의도한 구조와 텍스트에 적힌 구조는 다르다. 후자는 표로 뽑아야 보인다. 원문에 없는 값은 미기재로 남기고 추측으로 채우지 않는다. 작가 의도를 대조하는 절은 요청받았을 때만 만든다. scene-architect의 반대 방향(과거 ← 미래)이고, 새 사건을 제안하지 않는다.

쓰기 소유자 — 정본을 건드리는 유일한 지점

스킬왜 필요한가무엇이 다른가
remains-ledger-maintenance 캐논을 쓰는 주체가 둘이면 정본이 사라진다. 그래서 원장을 고치는 스킬은 하나뿐이고, 나머지 15개는 전부 읽기 전용이다. 다른 스킬은 파일을 쓰지 않거나 RUN_DIR에만 쓴다. 이 스킬만 prototype/remains.json을 제자리에서 고치고 pnpm verify && pnpm build가 경고 없이 통과하는지 확인한 뒤 완료|미완료|blocked로 보고한다. delete는 고아 참조까지 제거한다. schema 모드(2026-09-13 추가)가 새 도메인을 들이는 경로를 연다 — 기존 구조·명명·공개/비밀 분리를 유지한 채 구조만 만들고, 값은 add가 채운다.
narrative-rewriter (에이전트) 문체·시점 규칙을 매번 프롬프트로 설명하면 규칙이 흔들린다. 규칙을 에이전트 파일에 자기완결적으로 박아 둔다. 편집 범위가 호출자가 지정한 원고 범위뿐이고 도구도 read·grep·glob·edit·write로 제한된다. 재작성 단위도 다르다 — 논리·시점·보이스가 어긋나면 블록 전체를 다시 쓰고, 오탈자 같은 국소 결함만 문장 단위로 고친다. 판별 불가 블록은 고치지 않고 질의로 돌려준다.

그래프·증거 — 검수에 먹일 입력을 만든다 (2026-09-13 착륙)

검수 surface는 route manifest·anchor·compiled-content SHA-256·runtime evidence를 입력으로 요구한다. 산문은 그 요구를 채우지 못하고, 그것을 만드는 주체가 없어서 경로·엔딩 검사가 시작부터 UNVERIFIABLE이었다. 아래 둘이 그 칸을 채운다.

스킬왜 필요한가무엇이 다른가
story-graph-compiler 사람이 읽는 산문과 기계가 실행하는 그래프 사이에 번역자가 없었다. 검수에 위임하려면 먼저 실행 가능한 형식이 있어야 한다. reverse-outliner가 사람이 읽는 15필드 표를 뽑는 것과 달리, 같은 입력에서 같은 바이트가 나오는 JSON을 낸다(diff가 비어야 한다). 그래프의 형태를 정하지 않고(그건 story-graph-architect) 원고·카드에 있는 것만 옮기며, 없는 값은 미기재·open-edge·[HYPOTHESIS]로 남긴다.
route-replay-runner "수동 guard 읽기는 replay 증거가 아니다"가 검수 계약이다. 눈으로 훑은 추정을 계산된 기록으로 바꾼다. structural-critic·G05가 인과를 판정하는 것과 달리 "도달했다/안 했다"만 기록하고 품질을 판정하지 않는다. 그리고 no-terminal-defined(아직 안 씀)와 unreachable-terminal(도달 불가)을 구분한다 — 미완성을 결함으로 보고하면 도구를 못 믿는다.

검수 lifecycle — 만든 사람이 채점하지 않는다

스킬왜 필요한가무엇이 다른가
narrative-scene-after-generation 장면 하나가 규칙을 어긴 채 다음 장면으로 넘어가면 뒤에서 되돌리는 비용이 커진다. 넘어가기 전에 잠근다. continuity-auditor보다 넓고 structural-critic보다 좁다 — 한 장면 안에서 1인칭 정보 경계, 선택지 4필드, 후속 장면 존재, 클라이맥스 조기 소비를 함께 보고 장면 승인 차단 여부를 낸다. 후속 장면이 아직 없으면 발명하지 않고 UNVERIFIABLE로 둔다.
narrative-ending-route-review 엔딩은 결말 문장이 아니라 경로의 종결이다. 도달 가능성은 읽어서가 아니라 실행 증거로만 알 수 있다. narrative-multi-ending-integration이 엔딩 사이를 보는 것과 달리, 이 스킬은 한 경로 안을 본다. 6축 종결(서사·인물·주제·감정·선택 결과·기억 이미지)과 결과 5범주를 여기서 처음 판정한다. 수동 guard 읽기는 증거로 인정하지 않는다.
narrative-multi-ending-integration 각 엔딩이 좋아도 세트가 서로를 무효화할 수 있다. 배타성·한 회차 누적·지배 경로는 개별 검토로는 안 보인다. ID·manifest·앵커·본문을 교차 대조하고, 제목만 다른 변형 엔딩을 가려내고, 한 경로가 모든 배타 콘텐츠를 먹으면 그 엔딩을 재플레이 동기에서 제외한다. 균형을 자동 초엔딩이나 인공 잠금으로 맞추는 것은 금지다.

게이트 전문 — 판정을 격리한다

에이전트왜 필요한가무엇이 다른가
narrative-gate-specialist 게이트를 한 번에 다 채점하면 판정이 서로 번지고 리뷰어 취향이 섞인다. 게이트 하나를 독립된 시야로 본다. 담당 게이트만 채점하고 최종 등급·종합 점수를 내지 않는다. 다른 게이트는 직접 의존이 필요할 때만 언급하고 소유 게이트를 지목한다. GATE가 없거나 G01~G27 밖이면 input-blocked이고 파일을 쓰지 않는다. 점수를 목표 등급에 맞춰 올리거나 내리는 것도 금지다.

종합 — 흔들리지 않는 하나로 고정한다

스킬왜 필요한가무엇이 다른가
narrative-score-synthesis (G28) 메모 27개를 점수 집합으로 고정하지 않으면 G29·G30이 매번 다른 키를 만들어 버전 비교가 불가능해진다. 등급을 매기지 않는다 — 유효성(formalExportReady)과 다음 단계가 쓸 점수만 남긴다. 충돌 점수는 평균내지 않는다: 평균은 근거를 지운다. 같은 근본 원인의 finding은 병합하고 가장 높은 severity를 보존한다.
narrative-final-verdict (G29) 등급과 출시 준비도는 근거 위에서 한 번 확정돼야 하고, 상한 규칙(핵심 게이트 50 미만 → C 이하, Critical/Major 잔존 → Ready 금지)을 사람이 매번 재해석하면 판정이 흔들린다. 새 점수를 만들지 않고 G28 근거 위에서만 verdict 5개를 닫힌 enum으로 확정한다. 그리고 서사 출시 준비도와 제품·투자 승인을 구분한다 — 이 스킬은 후자를 결정하지 않는다.
narrative-report-assembly (G30) 사람이 읽는 문서 하나가 필요하고, 섹션 순서·키 개수·게이트 커버리지가 흔들리면 회차 간 비교가 불가능하다. 메모를 고치지 않는다 — 고쳐야만 보고서를 만들 수 있으면 export-blocked로 멈춘다. finding을 근본 원인 단위로 중복 제거해 하나의 수정 목록으로 만들고, 13개 섹션 순서와 공식 키 18개를 계약으로 고정한다.
