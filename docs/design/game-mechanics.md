# 게임 메커니즘 스펙

- 상태: 핵심 포크 4건 확정 / 잔여 2건 기본값 제안
- 정본: `prototype/remains.json`(원장). 이 문서는 **메커니즘 파라미터의 단일 출처**다 — 파라미터 변경은 여기서만 한다.
- 원장 쪽 연결: `narrativeRules.gameMechanics.reference`가 이 문서를 가리킨다. 세계 사실(엔딩 종류·출동 규칙·진엔딩 경로)은 원장에, 구현 규칙은 여기에.

## 코어 루프 (확정)

1. 괴수·히어로 교전 발생 — 회사는 싸우지 않는다(`company.combatPosition`). 우리 일은 끝난 뒤의 뒷정리다.
2. 협회에서 실시간 출동 요청 공문 도착 — 기존 `queuedEvent` 강제 발화로 표현. 마감은 정오(`prototype/stories/example.md:47`).
3. **동행 결정**: 채용된 로스터의 부분집합에서 사장이 1~2명을 고른다. 초기 로스터는 4인(`dusik`, `ru`, `banjang`, `taesan`)이고, 로스터는 "사람을 뽑는다" 기둥으로 확장된다. 미선택자는 배치 대상으로 남는다 — 선택이 곧 "무엇을 못 보게 되는가".
4. 현장 진행 — 분기점이면 조합 필수 이벤트, 아니면 이벤트 풀 가중 랜덤.

## 원장 기둥과의 연결

| 원장 기둥 | 루프에서의 표현 |
|---|---|
| `mainTheme`: "사람을 뽑고, 일을 맡기고" | 채용(로스터 확장) → 배치(동행 선택) 2단 구조 |
| `company.responsibilities`: 사람을 뽑는다 / 사람을 배치한다 | 지원자·채용 이벤트, 동행·잔류 배치 결정 |
| `company.responsibilities`: 사고에 대처한다 | 현장 이벤트의 조사/구조/안전 선택지 |
| `company.responsibilities`: 괴수 잔당을 처리한다 | 잔당 처리/관찰 선택(시퍼 포함) — `monsterRemnants` 규칙 준수 |
| `company.combatPosition`: 싸우러 가는 조직이 아니다 | 이벤트는 전투가 아니라 뒷정리·조사·구조·안전·문서다 |
| `example.md:47·53` 정오 마감 상시 압력 | 타이머 메커니즘의 캐논 근거(적용 대상은 중요 사건만) |

## 확정 결정

| 포크 | 결정 | 비고 |
|---|---|---|
| 동행 구조 | 사장 동행 (1~2명) | 원고 1인칭 유지 · 채용된 로스터의 부분집합(초기 4인, 채용으로 확장) |
| 조합 이벤트 | 분기점에서 조합 이벤트 필수 | 분기점 = 진엔딩 플래그가 갈리는 지점. 그 외는 풀 랜덤 |
| 진엔딩 판정 | 플래그 비교 + 종결 게이트 | 일반 엔딩·파산·사망 존재. 배타성(루↔배태산)은 플래그 상호 배제로 강제 |

## 동행 인원 트레이드오프 (1 ↔ 2명)

캐논 근거 — `example.md:55`: "조사팀은 많을수록 좋은 게 아니다. 사람이 늘어나면 현장에서 다칠 사람도 늘어나고, 협회에 제출할 보고서에서 책임져야 할 이름도 많아진다."

| 인원 | 이점 | 비용 |
|---|---|---|
| 1명 | 노출·책임 최소 | 현장 조치 슬롯 1 · 조합 이벤트 접근 좁음 |
| 2명 | 현장 조치 슬롯 +1(조사/구조/안전을 나눠 처리) · 조합 이벤트 접근 확대 | ① 사고 판정의 피해 후보가 인원수만큼 증가 — 동행자 부상 시 다음 디스패치 결원 ② 협회 보고서의 책임 이름 증가 — 실패·재심사 시 책임 슬롯 증가 |

- 부상은 사망이 아니다("경로 잠금 방지"의 사망 봉인과 일관). 부상자는 일정 디스패치 동안 동행 후보에서 빠진다.
- 사장 사망 트리거(잔여 결정 5)는 이 노출 판정 위에서 계산한다 — 동행 인원과 안전 조치 성공 여부가 노출 확률을 바꾼다.

## 경로 차트 작성 규약 (trueEndingRoutes)

- 노드 ID는 `M1`, `M2`, … 순번을 유지한다 — diff가 읽히고, 삽입은 번호를 늘리는 것으로 끝난다.
- 미확정 구간은 점선(`-.->`)과 `?` 노드로 표시한다. 한 차트에 둘 이상이면 **`Q1`, `Q2`처럼 서로 다른 ID**를 쓴다 — 같은 ID를 재사용하면 mermaid가 한 노드로 병합하고 뷰어도 서로 다른 구간을 잘못 연결해 그린다.
- 부분 확정 시에는 쪼갠다: `M1 --> M2 --> Q1["?"] --> E`.
- `?`는 삽입 예약석이다. 구간이 확정되면 그 자리를 실제 노드로 대체하고, `mermaid`와 `steps`를 같은 커밋에서 함께 갱신한다.

## 경로 잠금 방지 (필수)

분기점 요구 조합을 데려가지 않았거나 인물이 사망하면 진엔딩 체인이 조용히 잠길 수 있다. 아래 3원칙으로 강제한다.

1. **재등장**: 같은 조합을 요구하는 분기점은 다음 디스패치에서 한 번 더 열린다(기회 2회).
2. **대체 경로**: 마지막 기회에도 미충족이면 축소판 이벤트(다른 조합으로 열리는 불완전 버전) 또는 일반 엔딩 분기로 이동한다.
3. **명시적 상실 신호**: 잠김은 화면 텍스트로 알린다. 조용한 잠금 금지.

사망 시점 범위: 명명 인물의 사망은 (i) 사망 엔딩으로 회차가 종결될 때, 또는 (ii) 해당 인물의 진엔딩이 이미 잠긴 것이 명시된 뒤의 후반 사건에서만 발생한다. **진엔딩 체인이 열려 있는 동안 명명 인물은 죽지 않는다.**

## 콘텐츠 무결성 규칙 (테스트 대상)

- **콘텐츠 도달성**: 진엔딩 체인마다 **시작 상태에서** 만족 가능한 경로가 최소 하나 존재해야 한다 — 플래그를 세우는 이벤트가 실제로 도달 가능해야 한다(분기점 조합 포함). 잠김이 이미 발생한 상태를 요구하지 않는다.
- **잠금 무결성**: 체인 잠김은 반드시 명시 신호 이벤트를 거친 뒤에만 발생해야 한다 — 신호 없이 잠기는 상태 전이는 0건이어야 한다.
- **분기점 조합 커버리지**: 선택 가능한 모든 조합에 대응 이벤트가 존재해야 한다.
- 실패 경로에는 비용이 있어야 한다.
- 공용 이벤트는 유효 선택지 2개 이상.
- **비밀 게이트**: 원장에서 `secret*`·`hidden*` 계열로 표시된 모든 비밀 필드(현재: `association.secretSummoning`, `dusik.secretCausality`, `ru.hiddenIdentity`, `ru.separation.secretReunion`, `banjang.hiddenActivity`, `taesan.hiddenIdentity`, `taesan.secretScheme`, `monsterRemnants.secretOriginWorld`)는 공개 지식 게이트를 통과하기 전에는 이벤트 조건에 쓰지 않는다. 새 비밀 필드가 생기면 자동으로 이 목록에 포함된다.

## 잔여 결정 (기본값 제안)

1. **미동행자 오프스크린 행동** — 기본값: 잔류자 1줄 보고(예: 최반장 잔류 → 감시 보고서 진전). `impact: seed` 카테고리로 편입.
2. **랜덤 풀 3등급** — 기본값: 분위기(none) / 악화(complication, 비용 동반) / 복선(seed, 낮은 가중치).
3. **공문 UI 서식** — 기본값: `prototype/prototype-briefing-format.html` A안 재사용.
4. **표시 수치** — 미정: 자금·안전·평판 중 무엇을 노출할지. 파산 엔딩 전제상 자금 수치는 존재해야 함.
5. **종결 트리거(파산·사망)** — 기본값 제안: 사망은 **사장 본인**에게만 발생한다(명명 인물 사망은 "경로 잠금 방지"가 봉인). 발생 경로는 캐논 위협(`mainTheme`: 사고·낙석)과 잔당 조우 중 하나에서 안전 조치 실패가 겹칠 때 — 노출 판정은 "동행 인원 트레이드오프" 절을 따른다. 파산은 회사 자금 고갈 시. 세부 수치는 구현 단계에서 확정.
